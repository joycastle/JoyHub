# 能力字段读取：单变量对照

本轮仅修复 `capabilities_json` 的读取：对象数组提取文本 `value`，继续支持旧字符串数组。未调整索引内容、模型、阈值、权重、同义词、顾问流程或接口。

基线：`704e43723fa48a0883077ec1ecd5fea94d6ed33a`。2026-11-10 只读导出 134 条当前公开且可用资源；查询及预期资源在运行前冻结。相同输入运行修复前后应用服务，使用实际 BGE 和已存向量，repository mock 只提供预先过滤的快照。此对照不测试完整 HTTP、数据库延迟或实时权限变更。

这是 17 条诊断样本，不是独立留出集或全面相关性评测；其中字段诊断查询直接取自现有能力，用来验证解析行为，不能与普通任务查询混算产品收益。

观察：

- 14 个查询的资源 ID 顺序不变；3 个查询发生变化。
- “手机视口布局检查”：原先 4 条候选均未包含预期的响应式 HTML 报告设计；修复后该资源排第 1，原 4 条候选退出。
- “生成固定 16:9 舞台”（字段诊断）：由无结果变为动态网页幻灯片。
- “continue an existing audio clip”（字段诊断）：目标 AudioCraft 保持第 1，另 9 条候选被现有阈值逻辑过滤。减少候选是观察结果，不据此保证它们全部无用。
- “画图”仍为空，未解决口语表达召回。名称查询与两个无匹配样本不变。

结论：字段修复恢复了可验证的信息通路，并有局部收益；不足以证明画像+BGE 整体优于上游，也不支持同时调整其他策略。后续应单独研究仍然失败的召回路径。
